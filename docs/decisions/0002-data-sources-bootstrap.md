# ADR-0002: データソースのブートストラップ戦略

日付: 2026-06-10 / 状態: 採用(暫定ソースからの置換を前提)

## 背景

初期構築を行った開発環境のネットワークポリシーでは GitHub / npm / AWS S3 のみに
到達可能で、以下へアクセスできなかった:

- nlftp.mlit.go.jp(国土数値情報 N02 = 路線線形の正規ソース)
- cyberjapandata.gsi.go.jp(地理院タイル・標高タイル = 地表標高の正規ソース)

## 決定

「抽出済み中間形式」を挟み、上流ソースを差し替え可能にする。

| データ | 正規ソース | ブートストラップ | 置換手段 |
|---|---|---|---|
| 路線線形・駅位置 | 国土数値情報 N02 | mini-tokyo-3d (MIT) | `fetch` + `extract-n02`(レシピ4) |
| 地表標高 | 地理院 dem_png (DEM10B) | AWS Terrain Tiles (SRTM) | `refresh-dem` ワークフロー(レシピ5) |
| 地表テクスチャ | 地理院タイル(淡色) | —(ブラウザから直接取得可) | 不要 |

- 抽出済み線形(`data/sources/extracted/lines/*.geojson`)は上流がどちらでも
  同一スキーマ。`metadata.source` にプロビナンスを記録する。
- DEM タイルはキャッシュをコミットし、ビルドのオフライン決定性を確保する。

## トレードオフと注記

- mini-tokyo-3d の線形は実線路に沿って人手キュレーションされた高品質データだが、
  公的データではない。MIT ライセンス・出典表記の上で暫定利用し、N02 へ置換する。
- SRTM(Terrarium)は表層モデルのため**ビル街で地表標高が数〜数十m高く出る**。
  これは駅 T.P. の系統誤差になる(検証で 大手町 +30m 等を確認済み)。
  そのため深い駅の編纂値(深さ)はそのまま、地理院 DEM 化を最優先タスクとする。
